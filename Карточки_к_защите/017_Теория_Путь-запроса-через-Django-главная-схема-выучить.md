# Путь запроса через Django (главная схема — выучить)

> 017 · Теория с нуля · 1.4. Путь запроса через Django (главная схема — выучить)

```
Браузер: GET http://127.0.0.1:8000/detail/
   │
   ▼
Сервер разработки (runserver) ── интерфейс WSGI ──► Django
   │
   ▼
MIDDLEWARE (по списку сверху вниз): безопасность, сессии, CSRF, аутентификация
   │        → появляются request.session и request.user
   ▼
URL-диспетчер: ROOT_URLCONF = WebApp1/urls.py, перебирает urlpatterns сверху вниз,
   │           берёт ПЕРВОЕ совпадение  → product_detail_view
   ▼
View (products/views.py): obj = Product.objects.all()   ──► ORM ──► SQL ──► db.sqlite3
   │                      context = {"my_obj": obj}
   ▼
render(request, "product/detail.html", context)
   │   шаблонизатор находит файл (TEMPLATES → DIRS), подставляет контекст
   ▼
HttpResponse (готовый HTML) ──► MIDDLEWARE (в обратном порядке) ──► браузер
```

Ответ одной фразой: *«Запрос приходит на сервер, проходит через middleware, по `urls.py` находится представление, оно через модели берёт данные из БД, передаёт их в шаблон как контекст, `render` собирает HTML и возвращает его браузеру»*.
